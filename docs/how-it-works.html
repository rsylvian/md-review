1 · The round

The document is read once at startup, so the text holds still while you read it. Closing the tab is the handoff.

1

Agent opens it

Runs md-review draft.md backgrounded and waits. A local server renders the file.

2

You comment

Highlight a passage, type. Each comment saves to .md-review/ as you make it.

3

You close the tab

The server notices, prints the review to stdout and exits. That exit notifies the agent.

4

Agent edits

Applies the feedback and reopens for round two. Addressed comments resolve themselves.

2 · Why anchors, not line numbers

4 · Auto-resolve

On a later round each comment's remembered text is searched for in the new file. That single test decides everything, and needs no cooperation from the agent — editing by hand counts too.

still open

The text is still there, so the comment stands — re-pointed at its new offsets.

resolvedBy: "text-changed"

Picking between duplicates

When the remembered text appears more than once, the ≈40 characters either side decide; if those changed too, the occurrence index the comment was originally on breaks the tie. Proximity of raw offsets is deliberately not the signal — inserting a paragraph shifts every offset below it, which would make the wrong occurrence look closer.

5 · Knowing the tab closed

The page holds one Server-Sent Events stream open. Nothing is read from it — its existence is the signal, and close fires even if the browser crashes, which beforeunload does not. A grace window tells a reload apart from a goodbye.

Reload — the stream drops and comes straight back

Ctrl+C finalises too, so an interrupted session still hands over whatever comments exist. Every comment is written to the sidecar the moment it is posted, so nothing depends on a clean shutdown.
